MyJuliaToolbox.iDataSet — Type
abstract type iDataSet

Abstract base type for dataset implementations. Concrete implementations should define how to manage and access collections of data (e.g., in-memory datasets, lazy datasets, etc.).

Implementation Guidelines

Subtypes should typically implement:

  • Data access methods (e.g., iteration, indexing)
  • Data transformation operations
  • Metadata management
  • Data validation

Example

struct MyDataSet <: iDataSet
    data::DataFrame
    metadata::Dict{String,Any}
end

MyJuliaToolbox.iParameters — Type
abstract type iParameters

Abstract base type for parameter configurations. Concrete implementations should define how to store, validate, and access configuration parameters for algorithms, models, or workflows.

Implementation Guidelines

Subtypes should typically implement:

  • Parameter validation
  • Default value handling
  • Parameter serialization/deserialization
  • Parameter access methods

Example

struct ModelParameters <: iParameters
    learning_rate::Float64
    epochs::Int
    batch_size::Int
end

MyJuliaToolbox.nonpersisted_fields — Method
nonpersisted_fields(::Type{T}) -> Tuple{Vararg{Symbol}}

Return the field names of T that write_dataset should skip and read_dataset should tolerate as absent (defaulting to a sensible zero value).

Override this for any concrete iDataSet subtype that has optional or intentionally-omitted fields:

nonpersisted_fields(::Type{RSUDataSet}) = (:stepwise_scores_df,)

Automatic defaults by field type

  • DataFrame → DataFrame()
  • Union{Nothing, T} → nothing

Any other type requires the field to actually be present on disk.

MyJuliaToolbox.IO.ArchiveMedia — Type
ArchiveMedia(path::String)
ArchiveMedia(path::String; format::Symbol)

A media backend for archive files. Supports reading and writing datasets packed into .zip or .tar.gz (.tgz) archives.

The archive format is inferred from the file extension by default:

  • .zip → :zip
  • .tar.gz / .tgz → :tar_gz

Arguments

  • path::String: Path to the archive file (need not exist yet for writes)
  • format::Symbol: Override the detected format (:zip or :tar_gz)

Example

# Write
write_dataset(ArchiveMedia("output.zip"), dataset; overwrite=true)

# Read
dataset = read_dataset(ArchiveMedia("output.zip"))
dataset = read_dataset(MyDataSet, "output.tar.gz")

MyJuliaToolbox.IO.SQLDumpMedia — Type
SQLDumpMedia(path::String; db_type::Symbol=:mysql, in_memory::Bool=true, parameters_locator::Union{String,Nothing}=nothing)

A media backend that reads from SQL dump files (MySQL, PostgreSQL, etc.).

This source loads a SQL dump file into a SQLite database (in-memory by default) with automatic syntax conversion from the source database type to SQLite.

Arguments

  • path::String: Path to the SQL dump file
  • db_type::Symbol: Type of source database (:mysql or :postgresql). Default is :mysql
  • in_memory::Bool: Whether to use an in-memory SQLite database. Default is true
  • parameters_locator::Union{String,Nothing}: Optional path/URL root used by read_parameters

Example

source = SQLDumpMedia("dump.sql", db_type=:mysql)
df = read_dataframe(source, table="users")

Note

For complex databases with advanced features, consider using dedicated conversion tools like mysql2sqlite or pg2sqlite before loading with DatabaseMedia.

MyJuliaToolbox.IO.iSourceMedia — Type
abstract type iSourceMedia

Abstract base type for all media backends. Subtypes represent a specific storage or transport mechanism (file system, database, SQL dump, console, …).

Implementing a new media type

Declare your struct as a subtype of iSourceMedia:

struct MyMedia <: iSourceMedia
    # your fields
end

Then add methods for the operations you want to support. All methods are optional — unimplemented ones fall back to a descriptive ArgumentError.

OperationMethod signature to implement
Read a DataFrameread_dataframe(m::MyMedia; kwargs...) -> DataFrame
Write a DataFramewrite_dataframe(m::MyMedia, filename, df; kwargs...)
Write a log recordwrite_log_record(m::MyMedia, record::LogRecord; kwargs...)
Read dataset_read_dataset_impl(m::MyMedia; type) -> LoadedDataSet
Write dataset_write_dataset_impl(m::MyMedia, dataset; kwargs...)

Read-only vs write-only

A read-only media type (e.g. SQLDumpMedia) should implement only the read methods and explicitly throw ArgumentError in the write methods:

write_dataframe(m::MyMedia, args...; kwargs...) =
    throw(ArgumentError("MyMedia is read-only"))

Existing concrete types

TypeReadWriteNotes
FileSystemMedia✓ CSV/Arrow✓ CSV/Arrowformat inferred from extension
DatabaseMedia✓ SQLite✓ SQLitepass table= or query=
SQLDumpMedia✓ (converted to in-memory SQLite)✗read-only
ConsoleMedia✗✓ log/CSV to streamwrite-only

MyJuliaToolbox.IO._unescape_mysql_string_values — Method
_unescape_mysql_string_values(stmt::String) -> String

Single-pass conversion of MySQL backslash escape sequences to their SQLite equivalents.

MySQL uses backslash escaping inside string literals; SQLite does not. Conversions applied:

  • \' → '' (escaped single quote → SQLite literal quote)
  • \\ → \ (escaped backslash → literal backslash)
  • \n → newline
  • \r → carriage return
  • \t → tab
  • \b → backspace
  • \0 → (dropped; SQLite TEXT cannot store null bytes)
  • Any other \X → X (pass through the escaped character)

MyJuliaToolbox.Utils.add_days_convention — Function
add_days_convention(d::Date, delta::Integer; convention::Symbol=:following, weekends=[6,7], holidays=Date[])

Add delta calendar days to d and adjust the resulting date according to convention. Supported conventions: :following, :modified_following, :previous, :modified_previous.

  • :following: move forward to the next business day
  • :modified_following: following, unless it moves to the next month, then use previous business day
  • :previous: move backward to the previous business day
  • :modified_previous: previous, unless it moves to the previous month, then use following business day

weekends expects an array of integer weekday numbers (1=Mon .. 7=Sun), default [6,7]. holidays is an array of Dates to treat as non-business days.

MyJuliaToolbox.Utils.compare_dataframes — Function
compare_dataframes(left, right, keys, target_columns; kwargs...)
compare_dataframes(left, right, left_keys, right_keys, target_columns; kwargs...)

Compare two DataFrames using key columns and report only differences.

Positional arguments

  • left, right: DataFrames to compare.
  • keys: Key column(s) used on both DataFrames (Symbol, String, or vector).
  • left_keys, right_keys: Key columns per DataFrame when key names differ.
  • target_columns: Column(s) to compare. If omitted (nothing), all common non-key columns are used.

Keyword arguments

  • precision: Numeric tolerance (Real) applied to all numeric targets, or a dictionary per target column.
  • check_type::Bool=false: When true, report type mismatches even when values match.
  • title::AbstractString="": Optional label included in report/log lines to distinguish multiple comparisons.
  • logger::Union{Nothing,AsyncLogger}=nothing: Optional async logger sink.
  • io::IO=stdout: Output stream used for console report.
  • color::Bool=true: Enable/disable colored console output.
  • emit_console::Bool=true: Print report to console.
  • max_differences::Int=25: Maximum differences printed in the report.

Returns a DataFrameComparisonResult including counters and a detailed differences DataFrame.
