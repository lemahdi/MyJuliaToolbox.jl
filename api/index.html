MyJuliaToolbox.iDataSet — Type
abstract type iDataSet

Abstract base type for dataset implementations. Concrete implementations should define how to manage and access collections of data (e.g., in-memory datasets, lazy datasets, etc.).

Implementation Guidelines

Subtypes should typically implement:

  • Data access methods (e.g., iteration, indexing)
  • Data transformation operations
  • Metadata management
  • Data validation

Example

struct MyDataSet <: iDataSet
    data::DataFrame
    metadata::Dict{String,Any}
end

MyJuliaToolbox.iParameters — Type
abstract type iParameters

Abstract base type for parameter configurations. Concrete implementations should define how to store, validate, and access configuration parameters for algorithms, models, or workflows.

Implementation Guidelines

Subtypes should typically implement:

  • Parameter validation
  • Default value handling
  • Parameter serialization/deserialization
  • Parameter access methods

Example

struct ModelParameters <: iParameters
    learning_rate::Float64
    epochs::Int
    batch_size::Int
end

MyJuliaToolbox.IO.AsyncLogger — Type
AsyncLogger(source::iMediaSource; min_level::Symbol=:info, capacity::Int=1024, sink_kwargs...)

Asynchronous logger that queues records in-memory and writes them from a background task, so main execution paths are not blocked by sink IO.

Arguments

  • source::iMediaSource: Destination sink (e.g. FileSystemSource, DatabaseSource, ConsoleSource)
  • min_level::Symbol: Minimum accepted level (:debug, :info, :warn, :error)
  • capacity::Int: Ring buffer size. When full, new logs are dropped.
  • sink_kwargs...: Additional sink-specific options (e.g. table="logs" for DatabaseSource)

MyJuliaToolbox.IO.SQLDumpSource — Type
SQLDumpSource(path::String; db_type::Symbol=:mysql, in_memory::Bool=true)

A media source that reads from SQL dump files (MySQL, PostgreSQL, etc.).

This source loads a SQL dump file into a SQLite database (in-memory by default) with automatic syntax conversion from the source database type to SQLite.

Arguments

  • path::String: Path to the SQL dump file
  • db_type::Symbol: Type of source database (:mysql or :postgresql). Default is :mysql
  • in_memory::Bool: Whether to use an in-memory SQLite database. Default is true

Example

source = SQLDumpSource("dump.sql", db_type=:mysql)
df = read_dataframe(source, table="users")

Note

For complex databases with advanced features, consider using dedicated conversion tools like mysql2sqlite or pg2sqlite before loading with DatabaseSource.

MyJuliaToolbox.IO.read_dataframe — Method
read_dataframe(src; format=:auto, kwargs...)

Factory to read various input types into a DataFrame.

Supported inputs:

  • path::AbstractString — dispatched by file extension (.csv, .tsv => CSV; .arrow => Arrow). If format==:auto it will try Arrow then CSV for unknown extensions.
  • df::DataFrame — returns the same object.
  • tbl — any Tables.jl-compatible table — converts to DataFrame(tbl).
  • io::IO — use format keyword to specify :csv or :arrow, or :auto to try Arrow then CSV.

MyJuliaToolbox.IO.read_dataframe — Method
read_dataframe(source::SQLDumpSource; table::Union{String,Nothing}=nothing, query::Union{String,Nothing}=nothing, kwargs...) -> DataFrame

Read a DataFrame from a SQLDumpSource by loading the SQL dump into SQLite and querying it.

Arguments

  • source::SQLDumpSource: The SQL dump source to read from
  • table::Union{String,Nothing}: Table name to read from (optional)
  • query::Union{String,Nothing}: SQL query to execute (optional)
  • kwargs...: Additional keyword arguments (currently unused)

Returns

  • DataFrame: The queried data as a DataFrame

Note

  • If neither table nor query is provided, returns a DataFrame listing all available tables
  • The SQL dump is loaded into a SQLite database with automatic syntax conversion
  • For MySQL dumps, converts AUTO_INCREMENT, KEY definitions, and data types

MyJuliaToolbox.IO.write_dataframe — Method
write_dataframe(path_or_io, df; format=:auto, overwrite=false, atomic=true, kwargs...)

Write df::DataFrame to path_or_io.

  • If path_or_io is a path (string), the format is inferred from the file extension (.csv, .tsv, .txt → CSV; .arrow, .feather → Arrow) unless format is provided. By default atomic=true: data is written to a temporary file in the same directory and then renamed into place (safer against partial writes). Use overwrite=true to allow replacing an existing file. Set atomic=false to opt out of atomic writes.
  • If an IO object is provided, you must specify format when it cannot be inferred.

MyJuliaToolbox.Utils.add_days_convention — Function
add_days_convention(d::Date, delta::Integer; convention::Symbol=:following, weekends=[6,7], holidays=Date[])

Add delta calendar days to d and adjust the resulting date according to convention. Supported conventions: :following, :modified_following, :previous, :modified_previous.

  • :following: move forward to the next business day
  • :modified_following: following, unless it moves to the next month, then use previous business day
  • :previous: move backward to the previous business day
  • :modified_previous: previous, unless it moves to the previous month, then use following business day

weekends expects an array of integer weekday numbers (1=Mon .. 7=Sun), default [6,7]. holidays is an array of Dates to treat as non-business days.

MyJuliaToolbox.Utils._days_30_360_us — Function
yearfrac(i1::Integer, i2::Integer; basis=:actual365) -> Float64

Compute the year fraction between two integer dates (yyyymmdd) according to basis:

  • :actual365 (default): days / 365
  • :actual365_25: days / 365.25
  • :actual360: days / 360
  • :actual: days / 365.2425 (approx. Gregorian mean)

Returns a signed floating-point year fraction (positive if i2 > i1).
