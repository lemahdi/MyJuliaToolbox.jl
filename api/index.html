MyJuliaToolbox.iDataSet — Type
abstract type iDataSet

Abstract base type for dataset implementations. Concrete implementations should define how to manage and access collections of data (e.g., in-memory datasets, lazy datasets, etc.).

Implementation Guidelines

Subtypes should typically implement:

  • Data access methods (e.g., iteration, indexing)
  • Data transformation operations
  • Metadata management
  • Data validation

Example

struct MyDataSet <: iDataSet
    data::DataFrame
    metadata::Dict{String,Any}
end

MyJuliaToolbox.iParameters — Type
abstract type iParameters

Abstract base type for parameter configurations. Concrete implementations should define how to store, validate, and access configuration parameters for algorithms, models, or workflows.

Implementation Guidelines

Subtypes should typically implement:

  • Parameter validation
  • Default value handling
  • Parameter serialization/deserialization
  • Parameter access methods

    epochs::Int

MyJuliaToolbox._write_dataset_impl — Method
_write_dataset_impl(source::IO.MinIOMedia, dataset::iDataSet; type, overwrite, atomic, pretty)

Write dataset under the media's prefix with a folder's layout, each object streamed from memory (no temporary folder): the tables first, then parameters/, then data.json, then data_info.json last, as the mark of a complete dataset.

One LIST up front refuses keys that already exist unless overwrite, before anything is written. With atomic=true (default), a failure aborts the upload under way, deletes the objects this call wrote and, when overwriting, the rest of the old dataset (root tables, parameters/, data.json, data_info.json): the prefix is left with no dataset rather than a mix of old and new objects. Nested prefixes (runs, logs) are never touched. S3 has no multi-object commit, so a reader during the write can see a partial dataset; it lacks data_info.json until the end.

MyJuliaToolbox.IO.MinIOMedia — Type
MinIOMedia(bucket; endpoint, access_key, secret_key, region, prefix, format, tls_verify, part_size)

An iSourceMedia backend backed by a MinIO (or any S3-compatible) object store.

Each object is stored at key {prefix}/{filename} inside bucket. An empty prefix stores objects directly at the bucket root.

Arguments

NameDefaultDescription
bucket—Target bucket (create first with minio_create_bucket!)
endpoint"http://localhost:9000"Server base URL
access_keyenv MINIO_ACCESS_KEYAccess-key ID
secret_keyenv MINIO_SECRET_KEYSecret key
region"us-east-1"Region tag (MinIO ignores it)
prefix""Logical directory prefix inside the bucket
format:autoDefault DataFrame format: :auto, :csv, :arrow
tls_verifytrueSet false to skip TLS cert checks (dev/self-signed only)
part_size64 MiBBytes buffered per multipart part and per ranged GET (at least 5 MiB)

Streaming

Objects are written as they are produced, through a buffer of part_size bytes: an object that fits in one buffer is put in one request; a larger one is a multipart upload, one part per full buffer (one part uploads while the next fills, so at most 2 * part_size bytes are buffered). Above 1,000 parts the part size doubles every 1,000 parts, so an object stays under S3's 10,000 parts. Reads fetch the object in ranged GETs of part_size bytes into one buffer of the object's size. No temporary file is written either way.

Credential resolution order

  1. Explicit constructor arguments
  2. MINIO_ACCESS_KEY / MINIO_SECRET_KEY environment variables
  3. AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY environment variables

Example

using MyJuliaToolbox

media = MinIOMedia("analytics";
            endpoint   = "https://minio.example.com",
            access_key = ENV["MINIO_ACCESS_KEY"],
            secret_key = ENV["MINIO_SECRET_KEY"],
            prefix     = "datasets/2025/q1")

write_dataframe(media, "prices.arrow", df)
df2 = read_dataframe(media, "prices.arrow")

MyJuliaToolbox.IO._MultipartWriter — Type
_MultipartWriter(backend, key; content_type, part_size)

A write-only IO that uploads to the object key what it is given, as it arrives.

Bytes fill a buffer of part_size bytes. When the buffer is full and more bytes come, the upload begins (with content_type) and the buffer goes as part 1, uploaded by a task while a second buffer fills; each later full buffer waits for the part before it, then goes as the next part. So at most two buffers (2 * part_size bytes) are held. close puts the object in one request if no part went yet (an object of at most part_size bytes), else uploads the last part and completes the upload. position is the number of bytes written.

Use it through _with_multipart_writer, which aborts the upload when anything throws.

MyJuliaToolbox.IO.iSourceMedia — Type
abstract type iSourceMedia

Abstract base type for all media backends. Subtypes represent a specific storage or transport mechanism (file system, database, SQL dump, console, …).

Implementing a new media type

Declare your struct as a subtype of iSourceMedia:

struct MyMedia <: iSourceMedia
    # your fields
end

Then add methods for the operations you want to support. All methods are optional — unimplemented ones fall back to a descriptive ArgumentError.

OperationMethod signature to implement
Read a DataFrameread_dataframe(m::MyMedia; kwargs...) -> DataFrame
Write a DataFramewrite_dataframe(m::MyMedia, filename, df; kwargs...)
Write a log recordwrite_log_record(m::MyMedia, record::LogRecord; kwargs...)
Read dataset_read_dataset_impl(m::MyMedia; type) -> LoadedDataSet
Write dataset_write_dataset_impl(m::MyMedia, dataset; kwargs...)

Read-only vs write-only

A read-only media type (e.g. SQLDumpMedia) should implement only the read methods and explicitly throw ArgumentError in the write methods:

write_dataframe(m::MyMedia, args...; kwargs...) =
    throw(ArgumentError("MyMedia is read-only"))

Existing concrete types

TypeReadWriteNotes
FileSystemMedia✓ CSV/Arrow✓ CSV/Arrowformat inferred from extension
DatabaseMedia✓ SQLite✓ SQLitepass table= or query=
SQLDumpMedia✓ (converted to in-memory SQLite)✗read-only
ConsoleMedia✗✓ log/CSV to streamwrite-only

write_dataframe(path_or_io, df; format=:auto, overwrite=false, atomic=true, kwargs...)

  • If path_or_io is a path (string), the format is inferred from the file extension (.csv, .tsv, .txt → CSV; .arrow, .feather → Arrow; .xlsx → Excel) unless format is provided. By default atomic=true: data is written to a temporary file in the same directory and then renamed into place (safer against partial writes). Use overwrite=true to allow replacing an existing file. MyJuliaToolbox.IO._unescape_mysql_string_values — Method

Single-pass conversion of MySQL backslash escape sequences to their SQLite equivalents.

MySQL uses backslash escaping inside string literals; SQLite does not. Conversions applied:

  • \' → '' (escaped single quote → SQLite literal quote)
  • \\ → \ (escaped backslash → literal backslash)
  • \n → newline
  • \r → carriage return
  • \t → tab
  • \b → backspace
  • \0 → (dropped; SQLite TEXT cannot store null bytes)
  • Any other \X → X (pass through the escaped character)

Add delta calendar days to d and adjust the resulting date according to convention. Supported conventions: :following, :modified_following, :previous, :modified_previous.

  • :following: move forward to the next business day
  • :modified_following: following, unless it moves to the next month, then use previous business day
